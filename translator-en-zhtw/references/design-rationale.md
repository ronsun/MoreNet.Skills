# 設計依據：為什麼是「先寫再查」，不是「先譯再修」

（非操作參考。本檔解釋 skill 的設計決策與必須避免的做法，供理解與日後迭代。）

## 必須避免的做法：「直譯 → 規則修腔」

LLM 翻譯最直覺的流程是「先直譯，再套規則清單修掉翻譯腔，最後自檢」。這條路修得掉明顯病灶，但天花板是「乾淨的翻譯」，永遠到不了「像中文原著」。原因有四，理解它們才能真正避開：

1. **錨定效應**。第一稿直譯產生的英文骨架（資訊順序、句界、句構）會錨住後續所有修改；規則修補是在英文骨架上換零件，骨架本身動不了。先直譯等於先製造問題再清理，而清理永遠不徹底——這就是三遍法規定「第二遍不看英文句型」、audit.md 規定「失真要整句重寫、禁止打補丁」的原因。
2. **除錯天花板**。翻譯腔規則全是「不要 X」：不要虛主詞、不要被動濫用、不要代名詞鏈。把所有「不要」都做到，得到的是沒有錯的譯文，不是母語者會寫出的文章。**母語感是「有什麼」（資訊流、節奏、落點、聲音），不是「沒有什麼」。** 負面清單在原理上就到不了正面品質——所以 craft.md 是寫作課而不是規則清單。
3. **注意力稅**。要求模型翻譯時同時比對十幾類規則，模型會把算力花在「合規」而不是「寫好」上，產出機械式的規則滿足——每條都過，整體是死的。規則必須放在查核階段，不能放在生成階段。
4. **單位錯誤**。以句為單位處理，母語感就注定失敗：它存在於篇章層次——話題怎麼延續、節奏怎麼變化、判斷落在哪裡。1:1 句對齊正是「讀起來像翻譯」最深的特徵，所以工作單位必須是小節／段落群。

## 核心工法的依據

### 三遍法：deverbalization

職業譯者的共識工法：理解時脫離語言外殼（deverbalization，釋意理論 Seleskovitch/Lederer 的核心概念），表達時只從意思出發、不從原文句型出發。中文譯論傳統說法相同——思果《翻譯研究》：「翻譯是寫作」；余光中批評歐化中文的整個脈絡，指向的都是「照英文骨架寫中文」這一個病根。對 LLM 而言這個工法還有額外紅利：**分遍就是分心智狀態**，理解、寫作、查核各自用完整的注意力，避免三個目標互相稀釋。

「先寫再查」的忠實風險（重寫可能失真）用第三遍的嚴格對照來對沖：忠實從「翻譯時的束縛」變成「事後可驗證的檢查」，兩個目標解耦，各自做到最好。這比「翻譯時時時兼顧忠實與流暢」更可靠——兼顧的結果通常是兩頭都打折。

### 規則的正確位置：查核工具，不是翻譯方法

語言規則（hedge 禁升格表、語氣映射、台灣用語、量詞、症狀快掃）集中在 `audit.md`，定位為**第三遍的驗證工具**。關鍵在時機——寫作時讀 craft.md 吸收語感，寫完後用 audit.md 逐條驗證。同一批知識，放在查核位置是資產，放在生成位置是干擾（見上方第 3 點）。

### 出版級三審：盲讀編輯是關鍵角色

長文流程照搬出版社工法（譯者 → 中文編輯 → 校訂），其中**中文編輯不看英文**是整個設計裡最重要的一手：看過原文的腦袋會被原文帶著走，讀不出母語者的違和感；只看中文的編輯是唯一能模擬「台灣讀者盲測」的角色。這只有多代理做得到——同一個 context 內假裝沒看過英文是做不到的。編輯可能改出語意失真，所以後面跟一道只查忠實的雙語校訂，兩個角色的紀律互為保險。

多代理同時解決長文的工程問題：單一 context 品質衰退、跨段風格與術語漂移，用隔離 context＋共享定調筆記／術語表處理。

### 定調段：一致性的載體

跨段一致性靠兩個輕量載體：術語表（機械層）與定調段（聲音層）。定調段是 orchestrator 親自譯到滿意的樣稿，比任何風格描述都有效——風格用展示的，不用形容的。這同時是品質承諾機制：開工前就必須產出一段達標譯文，達不到就沒有開工的資格。

### 不詢問模式

規模分級由內容長度自動決定，不詢問使用者。品質是本 skill 的預設值；詢問只是把專業判斷推給使用者，且中斷工作流。

## 已知取捨

- **成本**：三遍法＋三審的 token 開銷是直譯的數倍到十數倍。這是明確的設計取向：品質優先。
- **極短文本**：一兩句話的翻譯，三遍法在心智上一樣走，但不需要外顯的定調筆記與落地儀式。
- **技術文件**：重寫自由度最低的文體（craft.md §7），三遍法仍適用，但第二遍的「自由」主要花在指令句式與條件前置，不是節奏與聲音。
- **忠實與母語感的殘餘衝突**：真衝突時優先序不變（語義 > claim strength > 術語 > 語用 > 流暢），寧可犧牲漂亮。

## 實戰增補：從整章翻譯回收的操作教訓

以下三條是實際跑完一整章（技術書，六百多段，三審全流程）後回收的教訓，已寫進 `long-document-workflow.md` 的對應步驟。記在這裡是為了保存「為什麼」。

### 1. 中文編輯的頭號失誤是 hedge 升格

盲讀編輯為了把句子改順，會**系統性地把弱主張改強**：may→會、suggest→證明、consider→就、probably 直接消失、「當初若…本可以…」的反事實假設寫成既成事實。實測一章下來，雙語校訂抓到的失真裡，這一類佔絕大多數——而且因為編輯看不到原文，他無從自我察覺。

這不是編輯不用心，是「順句」這個目標和「保留 claim strength」這個目標天生衝突：弱主張的字（可能、似乎、傾向）在中文裡讀起來就是比斷言鬆散，編輯的耳朵會想收緊它。因此對策不是提醒編輯小心，而是**明確畫紅線**（編輯 prompt 裡列出「強度一個字都不要動」），並讓下一關的校訂者**優先獵殺這一類**。這是三審流程裡「編輯負責母語感、校訂負責忠實」分工的具體兌現點。

### 2. 譯入既有語料，先蒐詞再開工

續譯一本書的後續章節時，新章的用詞必須和已出版的前文一致，否則整本像兩個人翻的。有效的做法是動筆前先對既有中文譯文做**字頻統計**，把競爭譯法（型別 vs 類型、建構子 vs 建構函式、串流 vs 資料流）按「多數派＋官方譯名」定案鎖進術語表。這比「邊翻邊猜、事後再統一」可靠得多——一致性是設計出來的，不是校出來的。定調筆記的術語表因此不只是「這篇要用的詞」，而是「這篇必須對齊的既有事實」。

### 3. 機械式終檢是獨立於三審的一道關

三審查的是語言（母語感、忠實）；但段數對不對、交叉引用連結有沒有掉、HTML 標記與實體有沒有壞、CRLF/BOM 有沒有被動到——這些是**程式該查的東西，肉眼一定漏**。所以流程最後獨立出一道機械式終檢，全部用腳本掃。特別是跨章書籍的交叉引用連結（「見第 X 節」），是最隱蔽也最常見的漏失，必須用「譯文連結數＝原文連結數」這種硬指標兜底。

附帶一條：術語一致性掃描會有**假陽性**。子字串比對會把「這類型別」誤判成違規的「類型」、「參數組成」誤判成「數組」。機械掃描給的是線索不是判決，命中一律回上下文確認再改。
