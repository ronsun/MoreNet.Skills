# 英 → 台灣繁體中文（母語等級）

這個 skill 的核心方法是 **LLM 翻譯 + 品質框架重寫**。純 LLM 直翻會無意識帶入英式骨架——尾修飾、虛主詞、代名詞鏈、被動僵硬。下方的「翻譯品質框架」與 `references/linguistic-rules.md` 就是用來把這些英式痕跡清掉，讓譯文讀起來像台灣人自己寫的。

---

## 兩種翻譯路徑

兩條路徑都是純 LLM 翻譯，差別只在要不要把每段隔離出去翻：

| 路徑 | 怎麼跑 |
|---|---|
| **標準模式** | 單一 agent 逐段翻譯 + 品質框架重寫。見下方「主流程」。 |
| **多代理模式** | orchestrator 分段、每段派一個翻譯子代理、再由整合者逐段重譯統一全篇。見 `references/multi-agent-workflow.md`。 |

**為什麼有多代理**：LLM 在長文單一 context 下會品質衰退、跨段風格與術語會漂移。多代理把每段隔離翻譯（context 乾淨），再由整合者統一全篇，藉此維持品質與一致性；代價是時間與 token 開銷高很多。內容愈長愈划算，短內容標準模式就夠。

**觸發時機：每次翻譯請求都先問使用者要走哪條，不自行決定。** 一律先問：

> 💡 這份要用哪種翻法？
> **1. 標準模式**——單一 agent 逐段翻，快、省 token。
> **2. 多代理模式**——每段獨立翻、再由整合者統一全篇，長文品質與跨段一致性較好，但較花時間與 token。
> （內容愈長愈建議多代理；短內容標準模式就夠。）

依使用者回覆執行：選標準 → 走下方「主流程」；選多代理 → 依 `references/multi-agent-workflow.md`。同 session 不重複問，首次決定後沿用（除非使用者改指定）。

翻譯子代理讀的濃縮規格在 `references/condensed-rules.md`；以下「主流程」是標準模式內容，也是多代理裡單段翻譯的品質基準。

## 主流程（標準模式：逐段落地）

### 步驟 1：分段

以自然段落為單位，不在段落中間切斷。單一段落過長（超過約 3000 字元）才強制再拆。

**逐段落地原則**：每個段落是完整閉合單元，譯完並寫入後才能展開下一段。段落 N 寫入成功是段落 N+1 開始的前提——翻譯過程隨時可能因逾時或上下文耗盡而中斷，未落地的譯文會全部丟失。

### 對每個段落依序執行 a → b → c

#### a. LLM 翻譯 + 重寫

直接從英文原文翻譯，並針對譯文套用下方「翻譯品質框架」與 `references/linguistic-rules.md`：結構重寫、歐化中文修整、文化／idiom 攔截、語氣與學術 hedge 處理、術語鎖定。

#### b. 自檢（套用下方「翻譯品質框架 → 自檢」，搭配 `references/linguistic-rules.md` §15 自檢快查表）

#### c. 寫入輸出檔案

等待寫入工具回傳成功，**才**展開下一段的 a。

---

## 預設輸出規範

- 只輸出最終譯文，不輸出診斷或過程，除非使用者明確要求。
- 目標語為**台灣繁體中文**，使用台灣慣用詞彙。
- 預設文體對齊原文文體，如：口語、學術、商務、行銷等。
- 逐段輸出。

衝突優先序：**語義忠實 > claim strength（主張強度）忠實 > 術語一致 > 文化／語用適切 > 流暢度**

---

## 翻譯品質框架（步驟 a 的具體做法）

步驟 a 的所有處理原則（結構重寫、歐化中文、文化／idiom 攔截、語氣映射、學術 hedge 保留、典型英中結構差異等）一律以 `references/linguistic-rules.md` 為準。

下面兩節是流程級約束，不在 references 中重複：

### 術語

- 首次出現用「中文譯名（English）」格式
- 無通行台灣譯名 → 保留英文，等使用者確認後再回填
- 全篇鎖定不混用；同段不出現中英不同稱呼

### 自檢（步驟 b）

對照原文與 `references/linguistic-rules.md` 各節，逐節問「這一段裡，這條規則該用的地方都用了嗎？沒用的地方是否有正當理由？」。

最低標準（少一項就算未通過自檢）：

- 段落中**每一個**該套用的 references 規則都實際套用了
- 譯文**語意忠實**於原文：沒有遺漏、增添、強度位移、因果顛倒、條件變事實、否定錯置
- 譯文**內部一致**：與本篇前面段落的術語、人名、組織名、稱謂、語氣層級一致

發現任何一項不過關 → **重翻該段**，不要原地修補（修補容易留下英式骨架殘跡）。
